# 第一次 Coding 练习

这个练习让 Loop 修复一个平均值函数：空切片与 nil 输入时会除零，非空输入需要保持原有行为。代码和测试会复制到本次运行的独立目录，不会修改你现有的项目。

## 开始

普通对话不需要 Docker。运行 Coding 练习前，启动本机 Docker，并准备固定版本的 Go 镜像：

```sh
docker pull golang:1.24-bookworm@sha256:1a6d4452c65dea36aac2e2d606b01b4a029ec90cc1ae53890540ce6173ea77ac
```

按 README 启动 Loop，打开本机网页：

1. 在设置中将模型请求上限设为 6。一次响应可以包含多个工具调用；工具调用总上限仍为 24。
2. 点“新任务”→“修复一个 Go 程序”，阅读授权范围。
3. 点“授权并运行练习”。模型自行决定读取、修改与再次测试的调用顺序。
4. 在执行轨迹中点击 `run_command` 查看退出码和输出；点击 `write_file` 查看真实文件 diff 与前后指纹。

模型可能无法在预算内完成。保留失败记录，先检查最后一次工具回执，再决定是否继续同一对话；新练习会创建新的副本。测试通过只代表这些现有用例通过，不等于任意输入都已证明正确。

## 可以检查的证据

默认目录为 `~/.loop/runs/<首轮运行 ID>/workspace/`，里面有 `average.go`、`average_test.go`、`go.mod` 和 README。追问沿用这个副本，每轮原始记录仍保存到各自的运行目录。

- `read_file` 返回文本和 SHA-256 指纹。
- `write_file` 只接受 `average.go`，要求提供读取时的 `expected_sha256`。不一致则返回 `file_changed`，不写入，模型需要重读。
- 成功写入保存实际修改前后文本、指纹与 diff。临时文件写完后再替换目标，避免中途留下半个文件。
- `run_command` 只接受 `go test ./...`；执行器实际加入 `-count=1` 禁用测试结果缓存。回执包含 stdout、stderr、容器实际退出码、测试时的源码指纹和清理结果。
- 非零测试退出码作为错误回执送回模型；无法确认执行状态或清理结果时停止运行。

指纹核对不是任意编辑器之间的原子并发锁：目前依赖单活跃任务、独立练习目录。不要一边运行一边手工编辑这个副本；接入共享真实仓库前需要更完整的写入协调。

## 执行范围

文件工具由本机 Harness 执行，仅访问固定练习文件；测试进程运行在 Docker 容器中。测试容器只有项目的只读挂载，没有本机仓库、Docker socket 或模型 API Key。测试与 go.mod 的内容受 Harness 校验保护。

容器断网、非 root、根文件系统只读，限制 CPU、内存和进程数。临时目录允许编译和执行 Go 测试，容器结束后移除。单次执行上限 90 秒，stdout 与 stderr 各最多保留 64 KiB。容器隔离仍依赖本机 Docker，不是任意不可信代码的绝对安全保证。

首次镜像下载需要网络；运行测试时不联网，`GOPROXY=off`、`GOSUMDB=off`、`GOTOOLCHAIN=local`。因此本练习不支持下载第三方依赖。当前没有通用 Shell、任意文件写入、自动安装依赖或任意仓库接入。

`LOOP_PUBLIC=1` 时后端拒绝 Coding 练习，包括继续已有的练习；网页隐藏入口。授权不会扩大普通对话的只读工具范围。

## 开发验证

```sh
go test -race ./...
npm ci
npm test
# 需要已启动的 Docker 与上述固定镜像，不调用真实模型：
LOOP_TEST_DOCKER=1 go test -race -run TestCodingDocker -v .
```

Docker 检查覆盖已知错误、修复后测试通过、容器隔离、超时清理和普通模式工具不被改写。
