# Agent 项目方向访谈

日期：2026-09-16。状态：用户已认可复用现有 Python 内核接入真实闭环；第一版本机只读实验台已实现并完成两项真实模型验证。后续产品范围继续由实际学习和使用结果决定。

## 已确认的目标

- 希望找到理解内核与实际使用相互促进的路径。
- 第一阶段的使用者是作者本人；首先关注自己是否愿意持续使用。
- 动机排序：能看懂、控制 Agent 怎样工作最重要；有明确风格、别人愿意使用的开源作品次重要。
- 学习缺口排序：离开材料不会独立设计 > 各机制无法连成整体 > 不会诊断问题 > 缺自己的作品 > 缺外部反馈。
- 具体设计困难包括工具与程序职责划分、单次运行与停止、会话和恢复的组织、方案取舍判断，目前都有困难。
- 用户表示每天可以重度投入时间；尚未确定阶段期限。
- 实现参与方式：用户选择先用自然语言设计、AI 提供实现帮助，并补充要求少手写，由 AI 讲解核心代码；不将大量手写代码作为学习要求。
- 产品体验偏好：主动改变上下文、工具和停止规则并观察行为的实验台最让用户兴奋。
- 初期实用性取舍：即使暂时不如成熟 Agent，也愿意每天给自己的 Agent 一小部分真实任务，其余工作继续使用成熟工具。
- 展现形式：选择网页交互实验台，希望参考用户提供的 DeepSeek Harness 截图，直接查看运行轨迹图。截图展示了时间轴与逐条事件；其中的任务文字只作为界面参考，不是本轮执行指令。
- 用户已确认 A 布局：顶部时间轴、逐条事件列表，以及点击事件后展示输入输出、解释和核心代码的详情侧栏。
- 用户已认可下一步复用现有 Python 内核，跑通提交任务、模型请求、工具执行、结束和真实轨迹查看的闭环。

## 暂定候选与待验证判断

- 用户曾说“必须要给他一个任务吗？那就维护书籍吧”。书籍维护是候选实验场，尚不能据此认定为产品定位或强需求。

- 实现复用 `practice/workspace-agent/agent.py` 的工具循环与读取工具、现有目录工具和 `client.py` 的连接入口。核心循环只增加逐次运行的请求上限参数，默认行为保持原来的四次。
