# Go 运行内核与 TypeScript 网页

Levon 的首要目标是让作者独立理解、判断和修改 Agent，而作者阅读 Go 最顺，因此采用 Go 运行内核与 TypeScript 网页。接受双语言的接口维护成本，以换取核心代码的可理解性和长期维护便利；现有 Python 实现保留作行为对照，不预设以后必须迁移为全 TypeScript。

依据见[技术栈调研](../language-selection-2026-09-17.md)。若产品重心转向复杂网页、TS 插件或 TS-only 内核复用，再根据实际收益重新评估。选型不构成端到端性能提升的承诺。

## 迁移顺序与验收

1. 保留 Python 基线 0358008、历史加载修改及已有记录；先澄清仍暂停的本机服务问题。
2. 先迁移 Go 后端，保持现有网页接口和只读范围；再将网页脚本转为 TypeScript，保留已确认的布局。
3. 用相同固定模型响应和真实文件验证：调用编号配对、同批回执、预算停止、路径拒绝和错误回传。
4. 历史查看保持只读，保留旧记录及其当时的源码；Go 版本的源码展示须对应实际构建，不能用后来改过的文件冒充历史。
5. 等价行为通过后，再验证真实模型调用与三个学习实验。学习实验由作者先预测，再运行、解释；不以助手跑过测试代替学习完成。

本决策的等价迁移已实施：当前入口为 Go 与 TypeScript，Python 对照保存在 python-reference 标签。首次迁移没有增加 Shell、写入、多 Agent 或插件系统。
